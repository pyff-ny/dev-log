fix(hvac-log): --dry-run 预览的结果列统一为全库口径

PR-279 · 更新: 2026-09-09T21:16:27-04:00

问题

--dry-run 预览的「结果」列把两个口径混在同一行：before 是全局 SELECT count(*)， 结果列却填当天要写的行数。多日库上每次导入都被预告成「整表将只剩这些行」。

实测（库里已有 2026-09-05，导入 2026-09-08）：

`` session 1 1 替换 1 ← 实际会变成 2 learning 5 5 替换 5 ← 实际会变成 10 market_rate 1 0 替换 0 ← 实际仍是 1 ``

write_all() 本身是对的（只删当天），一条数据都不会丢——只有预览是错的。 但预览存在的理由正是让人在确认前看出数据丢失，现在它每次多日导入都在喊狼来了。

kept 分支在 0.4.0 / 0.6.0 已经为同一类问题修过两次，这次把最后那个 else 一起修完。

改法

统一为全库口径，按写入语义分三算：

| 类别 | 表 | 结果 | |---|---|---| | ACCUMULATING ∪ DAY_KEYED | component_type, equipment, skill, session, work_day, job, skill_observation | 全库现有 + 其中新增 | | kept | 复盘没带对应键的 work_segment / question / learning_gap | 全库现有（原逻辑，未动） | | 其余按天替换 | learning, safety_observation, component_install, market_rate + 带了键的那三张 | 全库现有 − 当天现有 + 将写入 |

- 新增 DAY_KEYED、REPLACEABLE_DAY_COL 与 day_snapshot() - planned_new() 扩展到日键四表；planned_counts() 收 ref，component_install / skill_observation 按解析结果数（原先直接数 JSON 长度会高估） - 模块级分区 assert（7+3+4=14），以后加表漏归类直接在导入期报错 - 表头 现有/结果 → 全库现有/全库结果，并加一行口径说明 - write_all() / kept_tables() / CONDITIONAL_DAY_SCOPED 一个字符未改

验证

  • pytest apps/hvac_log/tests/ — 基线 256 passed，改后 257 passed
  • 新增 test_two_day_preview_matches_reality：两日库，四类分支各覆盖至少一张表
  • 手工两日复现：14/14 张表预览「全库结果」等于导入后真实 count(*)
  • 同日重导：预览正确显示无变化，与 test_import_is_idempotent 相符

顺带暴露的既有缺陷（本 PR 不修）

component_install 插入用 c.get("install_date") or day，DELETE 却按 session_date 清。 两者不一致时重复导入同一天会不断加行。新公式会如实预测这个增长（同日重导显示 2 → 3， 实测也是 3），以前的预览把它藏住了。要修的话另开一轮。
