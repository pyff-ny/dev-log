fix(dev-log-sync): correct PR diff base and display timestamps in NY time

PR-220 · 更新: 2026-08-27T12:23:39-04:00

Two bugs found right after shipping #218 (the non-Case PR sync path):

1. Why PR #219 never got a dev-log page: "Detect non-Case merged PRs" diffed merge^1..merge^2 directly to check for case-manager-app/cases/ paths. When the feature branch tip isn't a descendant of the target's pre-merge tip — which is exactly what happened across #217/#218/#219, all cut from the same stale point without rebasing — that raw diff also reflects everything that landed on develop in between (note_vault changes, a Case's release-notes.md), spuriously matching the exclusion and skipping an unrelated PR. Fixed by diffing from git merge-base instead, which isolates the PR's own changes regardless of branch staleness. 2. Wrong displayed timestamp** (reported against dev-log/improve/CASE-2026-091.html): render_case_page_html() printed released_at/updated verbatim. That case's release-notes.md had released_at set to the merge commit's UTC Z timestamp instead of the real local time recorded in case.md, and the raw UTC string was displayed as-is. Added _format_ny_local() so display always converts to America/New_York regardless of the stored offset — fixes it for both the Case path and the new PR path; date-only/naive values pass through unchanged.
