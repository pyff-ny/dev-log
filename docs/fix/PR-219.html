fix(health_panel): hide medication reminders under the spouse account

PR-219 · 更新: 2026-08-27T12:13:53-04:00

  • checkup.list_checkups() built the medication list unconditionally via list_medications(conn, today), ignoring the account it already uses to scope checkup_reports — so switching the 体检 tab to the spouse account still showed the same medication reminder that's only relevant to the self account.
  • The medications table has no per-person column (it's a single always-mine tracker, unlike medical_visits which has a person column), so the fix is a display-scope gate rather than a schema change: medications are only included when account is "self" or unset (no-filter callers keep seeing them); the spouse account gets an empty list.
  • /api/medications (a separate, currently frontend-unused endpoint) is untouched — not implicated in the reported symptom.

中文说明

  • checkup.list_checkups() 在拼装用药提醒列表时（list_medications(conn, today)）完全没有用到传入的 account 参数——而它旁边的体检报告（checkup_reports）已经按账户做了过滤，导致切到"老婆"账户时，看到的还是只该属于"我"这边的同一条用药提醒。
  • medications 表本身没有区分账户的列（它是一个"始终只属于我"的单一用药追踪器，不像 medical_visits 表那样有 person 列），所以这次修复是显示层面的账户过滤，不是改表结构：只有 account 为 "self" 或未传（无过滤调用）时才会包含用药提醒；老婆账户拿到的是空列表。
  • /api/medications（一个目前前端没在用的独立接口）没有改动——跟这次反馈的问题无关。
