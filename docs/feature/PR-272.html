feat(hvac-log): 接入 icon-toolkit 图标（冰蓝雪花 favicon）

PR-272 · 更新: 2026-09-07T05:09:43-04:00

把 hvac-log 的 favicon 从内联 🔧 emoji 换成 icon-toolkit 统一规范的图标。

图标

底 #0c1c2c，符号 #7fd6f5，六角雪花。512×512，内缩外框 420x420+46+46（与规范实测值逐像素一致），竖直渐变按规范的每通道 +22/-14。

配色不是拍的：从 icons/ 里 27 个既有 PNG 反推出真实色相后算最大空隙选的。冷色区最优是 274°（紫罗兰，17° 余量），全环最优是 112°（春绿，29°），但前者语义偏、后者的圆环加放射刻度会被读成"太阳/亮度"。最终选了语义最准的冰蓝——雪花的放射对称在这 27 个图标里形状独一无二，即使色相离 daily_checkin 只有 7°，缩到 Dock 尺寸也不会认错。

diff 为什么这么大

apply_icons.py 以 base64 内嵌，且 rel="icon" 和 apple-touch-icon 各存一份同样的 30912 字节，所以 index.html 从 2.9K 涨到 68K。这是该工具的既定行为。

hvac-log 是第一个 html_path 指向 git 仓库的 app——其余 26 条都指向 ~/toolbox-data/ 或 ~/toolboxes/。副作用是以后每次换图标都会在产品仓库产生一次 62K 的 base64 diff。如果觉得不划算，替代方案是把 PNG 放进 static/ 用路径引用（1 行 diff），但那会偏离 icon-toolkit "单文件可携带"的惯例——不过那个惯例的前提（HTML 复制到别处不丢图标）对 hvac-log 本来就不成立，它依赖整个 static/ 和 serve.py。

顺带修掉一个会让接入失效的问题

原第 7 行的 emoji favicon 排在注入块之后，留着会盖过新图标。已删除，现在文件里只有 1 个 rel="icon"。

验证

  • base64 解码后与源 PNG 字节级一致
  • APP-ICON-START/END marker 已写入，下次更新走替换而非叠加

注意

图标源文件 icons/hvac_log.png 在 ~/toolbox-data/icon-toolkit/（不受版本控制），所以本文件里的 base64 是这个图标在 git 里的唯一记录。

合并后需 mk serve stop hvac_log && mk serve start hvac_log 才生效——HTML 是读进内存的常量。
