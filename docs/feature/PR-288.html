feat(hvac_log): iPhone HEIC 照片直接上传，服务端 sips 转 JPEG（0.9.0）

为什么

2026-09-13 一张 HEIC 改了 .jpg 后缀去传：前端按后缀放行，服务端看文件头认出 HEIC 回 400。拒因只在页面顶上的 toast 闪 6 秒，而上传面板在时间线靠下的位置——人以为传上了，库里一行都没有，日志也只有一个 400。0.8.0 不收 HEIC 的前提是「改相机设置就好」，但手机里已经拍下的照片全是 HEIC。

改了什么

  • 服务端转码（serve.py）：sniff_mime 认出 HEIC → 新增 heic_to_jpeg() 调 macOS 自带 /usr/bin/sips 转 JPEG → 走原有落盘流程。库和盘上只存 JPEG。
  • sha256 与文件名摘要取上传原字节（sips 输出不保证逐字节稳定），先查幂等再转码。
  • 解不开的 HEIC → 400「这张 HEIC 转不了」；sips 不在 / 跑不起来 / 超 60 秒 → 500（RC_IO）。临时文件任何路径都清干净。
  • 拒因进日志：写端点的 400 记 WARNING … 被拒（400）：<原因>（截 500 字），500 记 ERROR。
  • 前端：checkFile 放行 .heic/.heif；上传失败原因写进面板内红色提示，下次点「上传」才清。
  • 文档/版本：VERSION 0.9.0、README、DESIGN §11.5 注记 + 新 §11.10；releases/v0.9.0/ 快照。

不变量

job_photo schema 与 mime CHECK 未改、无迁移（0.8.x 读得了 0.9.0 存的图）；响应 JSON 形状不变；其余写端点 MAX_BODY 256 KiB 不变；serve.py 退出码 2/4/130 不变；零新依赖。
