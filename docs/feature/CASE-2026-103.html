hvac-log-app-分析层 — 发布说明

CASE-2026-103 · 更新: 2026-09-06T10:37:10-04:00

新增分析层 apps/hvac_log/analyze.py，四个只读子命令：

| 子命令 | 回答什么问题 | |---|---| | faults | 哪些部件在坏，哪些部件还没写故障模式 | | sources | 哪个来源的说法可靠（source × verified 与证伪率） | | hours | 技术工时占多少 | | gaps | 哪些缺口还没真正解决 |

CASE-2026-102 交付存储层时按裁决五「不建任何 v_* 视图」，把派生逻辑全留给了分析层， 于是数据进得去、出不来。这次补上读取路径。

四条查询语义是判定而非事实，写成模块级常量并在 10-design/decisions.md 留证：

  • 「故障」= component_install.replaced_reason 非空
  • 证伪率分母 = 已核实条数，分母为 0 时给 null / —，不是 0%
  • 「技术工时」= seg_type IN ('service','install')
  • 「未解缺口」= resolved = 0 或 resolution = 'inferred'

第二条和第四条都不是顺手写的：用全部当分母会让查得少的来源显得干净， 而只查 resolved = 0 会漏掉自己糊弄过去的缺口——那恰恰是这套系统想抓的东西。
