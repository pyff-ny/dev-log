mk_project v1.0.0 → v1.1.0：统计层。

在 v1.0 已落库的 task_events 与 tasks.estimate_minutes/actual_minutes 之上，新增第 7 个 Tab「统计」，回答三个问题：

  • 估计准度——同时填了估计与实际工时的已完成任务，实际 / 估计的中位与平均比值、超出估计的占比，按分类与项目分组。零估计、只填一边的任务排除并单独计数，不静默丢弃。
  • 跨项目分类统计——每个分类的已结项/进行中项目数、平均周期（缺起始日的排除并计数）、逾期率（读各项目结项当时的快照，不重算历史）、阻塞总时长（成对的 blocked/unblocked 事件配对，未解除的开区间计至当前并单独标出还有几段在长）。
  • 复盘检索——在已结项项目的复盘正文里按关键词查找，%/_ 按字面匹配。

统计计算按三层架构（mk-serve-app-design/references/architecture.md）走独立 analysis/ 目录：一个 DuckDB 会话读取自身的 SQLite 库（stdlib sqlite3 取行喂 DuckDB 内存表，不用 ATTACH/sqlite_scanner，运行期零扩展零联网）算出统计，写两个 JSON 缓存；serve.py 只读缓存原样返回并附 age_seconds，全文不引入 DuckDB（AST 判定守着这条边界，比原计划的全文 grep 更严）；前端只 fetch + 渲染，不做任何统计计算。

launchd 每 30 分钟触发一次全新进程刷新缓存，不设过期——旧不旧由 Jia 判断，不是一个会在背后把数据抽走的机制。缓存缺失或损坏时接口返回 404 并给出可直接复制的命令，不是 500。
